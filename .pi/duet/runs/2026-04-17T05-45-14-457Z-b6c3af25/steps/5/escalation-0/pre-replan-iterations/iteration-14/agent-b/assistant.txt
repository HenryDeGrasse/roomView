Fixed the concrete security defect in `apps/api/src/roomplan-ingest.ts` by replacing the homegrown handoff/video token generation and hashing with Node crypto primitives.

What changed:
- token issuance now uses `randomBytes(...)`
- token hashes now use SHA-256 via `createHash(...)`
- handoff/video token verification now compares against the cryptographic token hash

Why: step 5 is high-stakes and requires a secure one-time handoff plus secure video upload token flow. The previous custom hash / fallback randomness was not appropriate for security-sensitive tokens.

I verified fixture checks still pass:
- `npm run verify:fixtures`
